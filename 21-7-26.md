## 1. Auto Scaling Groups (ASG) in AWS

An Auto Scaling Group (ASG) is an AWS feature that automatically manages the number of Amazon EC2 instances according to the workload and application requirements. It helps maintain application performance by increasing or decreasing the number of instances based on predefined scaling policies.

The instructor explained how an Auto Scaling Group maintains a desired number of EC2 instances. We learned about the minimum capacity, maximum capacity, and desired capacity settings. Minimum capacity defines the lowest number of instances, maximum capacity defines the highest number of instances, and desired capacity specifies the number of instances that the group should maintain under normal conditions.

For example, if a website experiences increased traffic, an ASG can launch additional EC2 instances to handle the workload. When traffic decreases, it can terminate unnecessary instances according to the configured scaling policies. Health checks can also help the ASG replace unhealthy instances automatically.

### Key Features of Auto Scaling Groups

- **Automatic Scaling:** Adjusts the number of EC2 instances according to demand.
- **High Availability:** Helps maintain the required number of healthy instances.
- **Cost Optimization:** Reduces unnecessary resource usage when demand decreases.
- **Health Monitoring:** Detects unhealthy instances and can replace them.
- **Integration with Load Balancing:** Can register new instances with a load balancer and remove terminated instances from its targets.

## 2. Drawbacks of Load Balancing

Load balancing distributes incoming network traffic across multiple servers or EC2 instances to improve application performance and availability. However, despite its advantages, load balancing also has certain limitations.

### Major Drawbacks

1. **Additional Cost:** Using a load balancer may increase infrastructure expenses because AWS charges for load-balancing resources and usage.

2. **Configuration Complexity:** Setting up listeners, target groups, health checks, security groups, and routing rules requires proper configuration and monitoring.

3. **Single Point of Failure if Not Designed Properly:** A poorly designed load-balancing setup can create a point of failure. Using an appropriately configured AWS Elastic Load Balancing service across multiple Availability Zones helps reduce this risk.

4. **Network Latency:** Requests pass through the load balancer before reaching the target server. This can introduce a small amount of additional latency.

5. **Uneven Traffic Distribution:** Depending on the load-balancing algorithm, session persistence, and application behavior, some instances may receive more work than others.

6. **Troubleshooting Difficulties:** Identifying the cause of errors can become more complicated because problems may originate from the load balancer, target instances, application, or network configuration.

7. **Application Compatibility:** Some applications require special configurations for session management, WebSockets, or client IP address handling to work correctly with a load balancer.

## 3. Relationship Between ASG and Load Balancing

Auto Scaling Groups and load balancing work together to improve the scalability and availability of cloud applications.

An ASG manages the number of EC2 instances, while a load balancer distributes incoming traffic among registered, healthy instances. When traffic increases, the ASG can launch additional instances, which can then receive traffic through the load balancer. When traffic decreases, the ASG can reduce the number of instances according to its scaling policies.

For example, during a sudden increase in visitors to a website, the ASG can add more EC2 instances, and the load balancer distributes requests among the available healthy instances. This combination helps maintain performance and makes efficient use of cloud resources.
